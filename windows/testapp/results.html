How to interpret this: these are two local, automated pixel-processing algorithms—not an LLM agent versus an LLM agent. The screenshot path encodes each full frame as PNG, decodes it, then scans the sorting lanes. The Perch-style path diffs each frame into 16×10 cells and processes changed-cell records. The elapsed-time figures include screenshot encode/decode latency and are not CPU-time counters. The Perch path is a browser simulation of the Windows eye format on generated moving frames; it is not a measurement from the installed IddCx feed or a physical display. Therefore this run does not establish real agent token savings, total system CPU savings, or energy savings.
